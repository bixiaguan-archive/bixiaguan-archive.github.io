# 语音转写深度校对

转写稿的错误有三类，必须分开处置，混在一起就会改错：

| 类型 | 特征 | 处置 |
|---|---|---|
| ASR 误识 | 读音相同或极近，写出来不成词/成错词 | 直接改正文，写 `asr_fixlog.json` |
| 主播口误、史实错误 | 读音正确、句子通顺，只是内容错了 | **不改正文**，进 `errata[]` |
| 主观表述、口语重复、语序 | 原话风格 | 一律不动 |

判断顺序：**先读音，后文义，再外部证据**。读音差得远的一律不改——那几乎一定是主播原话或口误，不是机器听错。

## 硬规则

1. **时间码行永不动**。只改字幕正文行；`apply_fixes.py` 已保证，但手工改时必须逐行确认 diff 里没有 `-->`。
2. **`find` 不得含换行**。需要跨块替换时，按原块边界手工拆成多条，每条落在单个块内；不要在块首/块尾留下孤立标点或空块。
3. **不做同义替换**：不改写、不删口语重复、不调语序（「读者→听众」这类一律禁止）。
4. **改专名前先查索引**。`bixiaguan_transcripts/notes/annotations.json` 里已有词条的写法就是既定语料，改动会把锚点打断。
5. **任何改动都要有第二种方法背书**（见下节「交叉验证」），单一依据的改动不进正文，进疑点清单。
6. **存疑即上报**。拿不准的写进清单交用户确认，不擅自"顺手改对"。
7. **附注与勘误的文字面向读者**。`label`、`explanation`、`note`、`correct`、`source` 会原样显示在网站上：不提 ASR、字幕、转录误作什么、块号、"已改""建议删去"之类校对过程；ASR 修正只记在 `asr_fixlog.json`。没有错误的地方不建勘误条目。

## 附注词条的写法

词条索引按名称查，读者展开后先看简介、再看各期怎么谈。三个字段分工不混：

- **`label`**：对象的名称，可括注别名、外文原名、所在地（「中华门（聚宝门）」「朱鲔石室（济宁金乡）」）。不写论断句，不写「本期：」。
- **`explanation`**：百科式简介，50–150 字，先说它是什么，再给该类对象的基本信息——人物：生卒年、国籍或籍贯、身份、代表作；建筑与遗址：省市县、始建与现存主体年代、文保级别；石窟造像与器物：时代、出土或原在地、现藏处；书籍文献：作者、成书年代、内容；机构：所在地、创立年代；概念术语：定义与通行用例。不转述主播观点，不写口语。
- **`episodes[].note`**：这一期怎么谈到它、主播的看法与现场见闻，写成书面语。
- **`source`**：简介所依据的可查文献、官网或条目（「Wikipedia「奉国寺」」「《营造法式》卷四」）。简介全凭节目时不写出处；不写「本期讨论」。
- 某条只是节目里的话题、找不到可以命名的对象（「帝国主义与科学知识」），标 `"topic": true`：仍在单期页面显示，不进词条索引；其 `label` 写话题名，`explanation` 概述讨论内容。
- 简介里的年代、归属、数量都要能查到；查不到的宁可不写。

## 交叉验证：至少两种独立方法

任何一条改动，从下面挑 ≥2 种互不依赖的方法验证，并在 `evidence` 字段写明用的是哪两种。

1. **读音反推**：把误写字按普通话（必要时加方言/日语音读）还原成音节，看候选词是否同音或仅差声母/韵母一位。`zhì→致/至`、`jí→集/奇` 都在射程内；`luò→没` 这种差太远，属主播改写不算误识。
2. **同音优先于"史实更常见"**：史实有两种称呼时，先取与误识读音最接近的候选，再看文义。**反例教训**：ep072「洛阳是神经」正确修法是「神京」（同音），不是「神都」。
3. **语篇自洽**：看上下文语法是否接得上。`日出处天子至` 后面紧跟「日落处天子**书**」，说明「至」是「致书」的「致」被截断。
4. **专名外部检索**：官网、博物馆藏品页、维基、权威工具书、学术论文。用 `web_access` 检索原文写法（含异体、旧译、日文汉字）。
5. **内部一致性**：同一期或相邻期里同一专名的其他出现处怎么写的，全库 grep 比对。
6. **数字与年代校验**：年代、尺寸、年代上限、编号（国保批次、窟号）逐一对表；不合的走勘误而不是改字。
7. **旁证链**：碑刻原文、铭文、账册（如《法隆寺资财帐》）、目录著录、拍卖/图录记录。
8. **锚点与索引体检**：改动前后跑 `python3 tools/audit2.py`，锚点缺失必须为 0。
9. **反向验证**：先假设"原文没错"，去找支持原文的证据。找不到再改。**照抄的教训**：ep097 主播说「一万日元上是圣德太子和梦殿」，看着像口误，查日本银行/国立印刷局后确认一万円 C 号券正面圣德太子、水印正是法隆寺梦殿——原文是对的，「修正」反而会制造错误。
10. **听感不可得时降级**：拿不到音频就别猜字形，标为「待确认」交用户。

## 单期作业流程

```
1  取料      wc -c tools/read/epNNN.txt；grep notes/annotations.json 查该期 errata/annotations
2  通读      必须全文读完（分段 offset/limit），不许抽样。第一遍只标疑点，不动手
3  逐段清单  每段问四件事：专名对不对？数字对不对？句子接得上吗？术语是行话还是错词？
4  验证      对每个疑点用 ≥2 种方法查证；查完分 A/B/C 三级
5  分级      A 高置信同音误识｜B 事实性口误（进勘误）｜C 存疑（列清单）
6  确认      A 级可直接改；B 级可直接立勘误；**C 级必须先报用户**
7  应用      /tmp/fix_epNNN.json → python3 tools/apply_fixes.py
8  校验      python3 build_index.py && python3 tools/audit2.py（锚点缺失 0）
             git diff 里 grep -c -- '-->' 必须为 0
9  记录      notes/asr_fixlog.json 自动写入；勘误改 annotations.json；PROGRESS.md 更新该期行
10 提交      git add <该期 SRT> annotations.json asr_fixlog.json PROGRESS.md
            git commit -m "细读校对 epNNN：主题"
```

### 逐段提问清单（第 3 步展开）

- 人名、地名、寺名、窟名、书名、机构名：逐个确认写法，含异体与旧译。
- 朝代/年号/公元年：与史书、铭文、著录对表；注意「贞观」「开元」这类易混。
- 数字：尺寸、年份、数量、比例（"二点三"这种尤其危险，见 precedents）。
- 佛教/建筑/考古术语：斗拱部件（批竹昂、计心偷心、慢栱、泥道栱、令栱）、龛形（殿形龛/帐形龛）、地层与墓葬术语。
- 外文残词：`ador`、`MISS Vanderbilt` 这类英文碎片，能按音还原就改，还原不了就上报。
- 引文：经史原句必须查原文（如《隋书·倭国传》「日出處天子致書日沒處天子無恙」）。

## 改动分级与上报格式

- **A 级（可直接改）**：同音/近音 + 文义成立 + 有外部或内部旁证。
- **B 级（可直接立勘误）**：读音无问题、句子通顺，但事实、年代、归属、尺寸有误。
- **C 级（必须上报）**：仅凭读音像、无法外部印证；或涉及专名但搜不到结果；或改动会影响既有附注锚点而语义不确定。

C 级上报用 `references/report-template.md` 的表格：位置（行号/时间码）、原文、建议、类型、依据、置信度。同时列出**核对无误清单**——让用户看到"哪些是查过才放过的"，而不是"没看出来"。

## 收尾自查（每次提交前）

- `python3 build_index.py` 通过，无异常输出。
- `python3 tools/audit2.py`：`锚点在全文中找不到：0`。出现 `MISS ('annotations', ep, subtitle, anchor, keyword)` 就是改动打断了锚点，回退或同步修 `annotations.json`（`id/keyword/label/explanation/episodes[].anchor` 全字段）。
- `git diff --unified=0` 里不含 `-->`。
- `PROGRESS.md` 该期行写清：ASR 处数、勘误条数、附注增补/补挂、以及核过但未改的项。
- `asr_fixlog.json` 与本轮实际改动条数一致（`apply_fixes.py` 输出「合计：修正 N 处，跳过 M 处」，跳过数必须解释）。
