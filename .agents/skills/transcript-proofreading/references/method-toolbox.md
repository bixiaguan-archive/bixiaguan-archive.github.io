# 验证方法工具箱

每条候选改动至少用两种。这里写清具体怎么下手。

## 1. 读音反推

1. 把误写字拆成拼音（含声调），必要时叠方言音、日语音读（漢音/呉音）、英文原词音。
2. 列出同音、近音候选（同韵异声母、同声母异韵、前后鼻音不分、平翘舌不分、n/l 不分）。
3. 用文义筛掉不成立的候选；剩下的按「读音最接近者优先」排序。

判定尺度（这条是用户明确要求过的）：

| 差异 | 例 | 处置 |
|---|---|---|
| 完全同音 | 至/致 zhì；账/帐 zhàng | 可改 |
| 差一个声母或韵母 | 集 jí / 奇 qí；屋架 jià / 无极 jí | 可改，但要第二种证据 |
| 差声调 | 有/又 | 可改 |
| 声母+韵母都不同 | 落 luò / 没 mò | 不改，视为主播改写 |
| 完全另一个词 | 神经 / 神都 | 不改（除非同音候选另有其人） |

## 2. 专名外部检索

检索顺序（命中率高到低）：

1. 官方页面：博物馆藏品页、世界遗产/国保名录、寺院官网（如 `horyuji.or.jp`）、教科文组织文件。
2. 工具书：kotobank（日）、大辞泉、中国大百科全书、`词典网`。
3. 维基（中文/日文/英文三语对照，用日文条目校汉字写法）。
4. 学术：CNKI 摘要、考古报告著录、图录书名。
5. 地图与行政区划：确认乡镇归属（如「象明乡」「洪水泉乡」）。

检索技巧：
- 用**疑似错误写法**先搜一次，若无结果或结果都指向同一正确词，说明是误识。
- 中文查不到就换日文/英文关键词（法隆寺 = `法隆寺` / `Hōryū-ji`）。
- 数字类专名（拱高、坐席数、尺寸）要找到**两个**独立来源再用。

## 3. 语篇自洽

看三处：前后分句的语法衔接、代词指代、量词与中心词是否搭配。
典型信号：字后面紧跟一个孤立的单字（「至，……书」），往往是上一句被截断的词。

## 4. 内部一致性（全库 grep）

```bash
grep -n "关键词" tools/read/epNNN.txt          # 本期其他出现处
grep -rn "关键词" bixiaguan_transcripts/*.srt  # 全库
python3 - <<'EOF'
import json
d=json.load(open('bixiaguan_transcripts/notes/annotations.json'))
print([a['keyword'] for a in d['annotations'] if '关键词' in a['keyword']])
EOF
```

同一专名全库若已统一为某写法，改动前先想清楚要不要全库统一——通常只改误识那一处，不要顺手批量替换。

## 5. 数字与年代校验

- 朝代↔公元年：用年表或维基年表条目双向核（如 唐穆宗 820–824、梦殿 739）。
- 早期木构上限：南禅寺 782、佛光寺 857、法隆寺西院上限 670、法起寺三重塔 706。
- 尺寸/规模：玉虫厨子 2.33 m、橘夫人厨子约 2.63–2.7 m、圣路易斯拱门 192 m。
- 批次编号：国保「国七」、窟号、品数（法隆寺献纳宝物约 300 件）。

## 6. 旁证链

优先找同时代的实物/文本证据：碑刻原文、铭文（释迦三尊 623、药师 607）、《资财帐》（739）、目录著录（《石渠宝笈》续编/再编之别）、拍卖与图录。

## 7. 锚点与索引体检

```bash
python3 tools/audit2.py | grep -E "锚点在全文中找不到|MISS"
```

改动命中附注/anchor 时，同步改 `annotations.json`：

- `annotations[]`：`id`、`keyword`、`label`、`explanation`、`episodes[].anchor`（必要时 `note`）。
- `errata[]`：`keyword`、`label`、`original`、`anchor`。

`audit2` 归一化会跳过 `《》·・‧\u00b7\u30fb` 与空白，所以标点差异不会误报，但字面不同会。

## 8. 反向验证（防「改出错误」）

改动前强制问一次：**原文有没有可能本来就是对的？**

做法：用原文写法直接检索，若能找到支持它的权威页面，就放弃改动。
判例：ep097「一万日元上圣德太子和梦殿」看似口误，实为一万円 C 号券正面圣德太子、水印法隆寺梦殿，原文正确。

## 9. 听感不可得时的降级

没有音频就**不要**凭"像"去改字形。降级处理：
- 记入疑点清单 C 级；
- 或记入 `tools/uncertain.md`；
- 正文保留原样。

## 10. 改完的机械复核

```bash
git diff --unified=0 bixiaguan_transcripts/epNNN_*.srt | grep -- '-->' | wc -l   # 必须 0
python3 build_index.py >/dev/null && echo build-ok
python3 tools/audit2.py | grep -c "锚点在全文中找不到：0"
```

`apply_fixes.py` 的三种结果都要读懂：`MISS`＝find 没匹配上（多半含换行或字打错）；`AMBIGUOUS`＝多处出现却未限定 subtitle（改加 `subtitle` 或 `all`）；「跳过 M 处」必须在提交说明里解释。
